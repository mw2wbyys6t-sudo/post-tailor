# OmniDraft 竞品调研、差异化定位与上线前 PRD

- 文档版本：1.0
- 日期：2026-11-20
- 对应产品版本：v1.6.0（上线候选）
- 调研方法：公开官网、应用商店、媒体报道与行业盘点；未接触任何竞品后台或私有数据
- 证据标记：`[官方]` 官网/应用商店；`[媒体]` 第三方报道/盘点；`[推断]` 基于公开信息的判断

---

## 一、结论（TL;DR）

1. **国内一键分发工具的主战场是“平台数量 + 账号矩阵 + 团队协作”**：蚁小二覆盖 40+ 平台 `[官方]`，易媒助手覆盖 70+ 平台 `[官方]`，简媒宣称覆盖 95% 新媒体平台 `[媒体]`。它们解决“发得快”，但公开评价普遍指出“差异化适配有限、仍需手动优化” `[媒体]`。
2. **“本地优先 + 真改写 + 真数据”仍是空位**：直接对标的 Postudio 已提出本地优先与 AI 改写，但仍处于 Alpha，平台均标注“即将推出” `[官方]`；Postiz / Mixpost 主打自托管与数据归属，但不覆盖国内图文平台 `[官方]`。
3. **OmniDraft 不应拼平台数量**，应把定位收紧为：**个人创作者的本地内容分发工作室——不发假数据、不做搬运式分发、把 4 个图文平台做深**。

## 三、关键发现

1. **“平台多”是入场券，不是差异点。** 40–95+ 平台的宣传已高度同质化；公开报道反而把“差异化适配有限、需手动优化”列为主要短板 `[媒体]`。这为“少平台、深适配”留下空间。
2. **账号信任是国内用户的真实顾虑。** 行业盘点明确建议优先选择“不存储明文账号密码、走官方授权”的方案 `[媒体]`；云端托管会话会增加风控与泄露焦虑。OmniDraft 的本地钥匙串 + 本机运行正好对应。
3. **AI 写作正在普及，但“平台原生改写”仍稀缺。** 易媒助手、有一云都已接入 AI 写作 `[官方]`，但公开能力描述多集中在“生成/排版”，不是“同一篇内容按平台规则重组 + 质检”。
4. **本地优先已被验证，但国内尚未成型。** Postudio 的本地优先 + AI 改写路线与 OmniDraft 一致，但平台仍是“即将推出” `[官方]`，说明窗口期仍在。
5. **“真实数据”正在成为信任资产。** 竞品普遍提供数据统计，但用户难以判断哪些是平台真实回拉、哪些是估算。OmniDraft 的“没有就不显示、不用 0 冒充”是可被感知的差异。

## 四、差异化定位与建议

### 4.1 一句话定位

> **OmniDraft：个人创作者的本地内容分发工作室。一稿按平台重写，发布后回拉真实数据；没有假数据，账号与内容都留在你的电脑里。**

### 4.2 三个支柱

1. **真改写**：不是复制到四个平台，而是按平台结构、语气、篇幅重新组织，并给出可追溯的七维质检与问题单。
2. **真数据**：只展示本机文章、真实登录状态、真实发布结果与回拉数据；没有回拉就显示“—”，不预置人群画像和平台热度。
3. **真本地**：桌面运行、凭据进系统钥匙串、文章/画像/日志不出本机；AI 可选且自带 Key。

### 4.3 明确不做什么

- 不做 40+ 平台矩阵，不追视频、私信、团队权限。
- 不做云端账号托管，不引入平台人群画像/热度估算。
- 不做“保证爆款”的承诺；质检分只是代理指标。

### 4.4 建议的目标用户

- 主要写图文、同时运营 2–4 个平台的技术人/职场人/独立创作者。
- 在意账号安全与数据归属，不愿把账号会话交给第三方 SaaS。
- 已经用过一键分发工具，但对“复制粘贴式分发”的效果不满意。

## 五、上线前 PRD（v1.6.0）

### 5.1 核心用户旅程（P0）

```
首次启动（空白库）
  → 建立画像（9 个关键问题，可跳过称呼）
  → 可选：配置 AI（DeepSeek，自带 Key）
  → 登录平台账号（CSDN / 公众号 / 知乎 / 小红书）
  → 新建或导入文章
  → 选择平台 → 智能改写
  → 查看平台版本 + 质检分 + 调整清单
  → 发布前检查（阻断项/提醒项）
  → 自动发布 / 复制稿
  → 发布记录 → 回拉真实数据
```

完成条件：至少 1 篇文章完成改写，并在至少 1 个平台产生发布记录（自动发布或复制稿）。

### 5.2 功能要求

| 模块 | 要求 | 状态/边界 |
| --- | --- | --- |
| 首次启动 | 空白库，不预置文章、记录、统计或演示数据 | 老版本演示数据在升级时清理 |
| 用户画像 | 9 个关键问题：称呼、身份、领域、专业程度、目标、读者、表达风格、避免表达、发文节奏 | 全部本机保存；重新问答预填旧答案；中途退出不丢原画像 |
| 画像生效 | 转为可执行约束写入改写计划；表达风格影响本地开头；AI 模式完整执行 | 与平台硬性规则冲突时在风险提示中标注 |
| 改写 | 4 平台确定性引擎；配置 AI 后走计划→成稿→质检→修复 | AI 失败自动回退本地；不编造原文没有的事实 |
| 质检 | 七维加权 + P0 硬门槛；问题可定位 | 分数是代理指标，不承诺流量 |
| 发布前检查 | 空标题/空正文/标题超限/小红书无图等为阻断；篇幅、代码块、base64 图片等为提醒 | 阻断项不可发布；提醒项可继续 |
| 发布 | 已登录且通道可用时自动发布；否则生成复制稿 | 失败记录可重试；失败原因写入记录 |
| 数据回拉 | CSDN/知乎/公众号状态；小红书明确“不支持” | 拿不到就显示“—”，不用 0 冒充 |
| 定时发布 | 应用运行中到点执行；错过标记 | 关闭应用不后台执行 |
| 备份恢复 | 全量 JSON，不含密钥 | 导入校验格式；恢复后重新登录 |
| 自动更新 | 启动后台检查、自动下载、提示重启 | 更新来自本仓库 Release |
| 诊断 | 本机日志、自动轮转、手动导出 | 不上传；不含正文/Key/凭据 |

### 5.3 明确的非目标

- 团队协作、账号矩阵、40+ 平台、视频发布、私信聚合。
- 云端同步、账号会话托管、任何形式的人群画像/热度估算。
- 自动刷量、自动互动、绕过平台风控。

### 5.4 关键异常与恢复

| 异常 | 处理 |
| --- | --- |
| 平台登录失效 | 账号中心显示“需重新登录”，发布前检查阻断自动发布，回退复制稿 |
| 平台接口变化/发布失败 | 记录状态“失败”+ 原因；可重试；写本机日志 |
| AI 超时/返回异常 | 回退本地引擎；不扣 AI 润色次数（润色失败不计数） |
| 本地存储接近上限 | 设置页提示；可清理草稿；建议改用图片链接 |
| 更新下载失败 | 提示错误；保留当前版本可继续使用 |
| 应用崩溃 | 主进程/渲染进程错误写入本机日志；用户可导出 |

## 六、本次 v1.6.0 已落地的优化

1. **移除全部静态/伪造数据**：删除受众嗅探页、平台人群画像、热门话题、画像强度；平台只保留写作规则。
2. **画像升级为 9 个关键问题**：新增专业程度、表达风格、避免表达；去掉随机昵称，改为用户填写。
3. **画像真实作用于改写**：生成 `【创作者偏好】`/`【写作约束】`，进入 AI 提示词；表达风格影响本地开头钩子；emoji 与小红书规则冲突会提示。
4. **画像页动态推导**：创作倾向、平台推荐、读者/语气建议全部由答案在本机计算，并明确“不上传、不使用平台数据”。
5. **本地诊断日志**：主进程 + 渲染进程错误、发布/回拉失败写入本机日志；设置页可导出或打开目录；单文件 1.5 MB 轮转。
6. **发布前检查保持并复用**：单条与批量发布共用同一套阻断/提醒规则。
7. **README 与定位更新**：新增“与其他分发工具的区别”，明确本地优先、真改写、真数据、4 平台聚焦。
8. **版本号提升到 1.6.0**，作为上线候选。

## 七、上线就绪审查（Production Readiness Review）

> 结论：**可作为公开测试版（Open Beta）发布；不建议在缺少代码签名与平台接口回归的情况下称为“商业正式版”。**

### 7.1 就绪矩阵

| 维度 | 状态 | 证据/说明 |
| --- | --- | --- |
| 功能完整性 | Pass | 4 平台改写、发布、回拉、备份、更新、诊断均有实现；`npm test` 4/4，`npm run eval` 全阈值 |
| 本地优先与隐私 | Pass | 内容/画像/日志本机；凭据走系统钥匙串；CSP 已配置；无遥测 |
| 安全基线 | Pass（有例外） | `contextIsolation: true`、`nodeIntegration: false`、CSP、外部链接走系统浏览器；无签名见 7.2 |
| 发布前校验 | Pass | 阻断项/提醒项，单条与批量复用 |
| 失败恢复 | Pass | 复制稿回退、失败记录重试、AI 回退本地、本机日志 |
| 可观测性 | Pass（本地） | 本机诊断日志；无云端监控（设计取舍） |
| 备份/恢复 | Pass（未演练） | 导出/导入可用；未做真实换机恢复演练 → Follow-up |
| 自动更新 | Pass（回滚未验证） | GitHub Release + electron-updater；未验证失败回滚 → Follow-up |
| 平台接口稳定性 | 风险 | 依赖平台页面/接口，可能随改版失效 → 每次发布前手工冒烟 |
| 分发与签名 | 例外 | Windows 未签名；macOS 未公证 |
| 容量/存储 | 风险 | localStorage 约 5 MB，base64 图片占用大；已有 3.5 MB 预警 |

### 7.2 阻断项与例外

| 类型 | 项 | 处理建议 |
| --- | --- | --- |
| 阻断（商业正式版） | Windows/macOS 安装包未签名 | 申请代码签名证书；Windows 至少 Authenticode，macOS 需 Developer ID + 公证 |
| 例外（可发布测试版） | 未签名导致 SmartScreen/未知开发者提示 | 在下载页与 README 明确说明；提供校验值 |
| 例外（平台风险） | 小红书浏览器辅助发布依赖页面结构 | 发布前手工冒烟；页面改版时回退手动并提示 |
| 例外（数据能力） | 小红书不支持回拉、公众号仅状态 | UI 明确显示“不支持/—”，不承诺阅读数据 |
| Follow-up | 自动更新回滚未实测 | 下一版本做一次“旧版本→新版本→回滚”演练 |
| Follow-up | 备份恢复未做换机演练 | 用两台环境做一次导出/导入恢复 |
| Follow-up | 平台接口无自动契约测试 | 每次发布前跑 4 平台登录/发布/回拉手工清单 |
| Follow-up | 本地存储 5 MB 上限 | 规划迁移 IndexedDB/本地文件，或强制图片外链 |

### 7.3 发布观察与回滚

- 发布后观察窗口：24–48 小时，重点看启动失败、更新失败、发布失败日志（用户主动导出）。
- 回滚路径：保留上一版本安装包与 Release；electron-updater 支持重新下载旧版本，但需人工指导。
- 成功标准：安装成功、首次启动空白库、画像可完成、4 平台至少 1 个真实发布成功、备份可导出。

## 八、发布建议

1. **定位文案**：用“本地内容分发工作室”，不要用“全网一键分发”；避免与 40+ 平台工具正面比较数量。
2. **发布节奏**：先发 Open Beta（v1.6.0），收集真实发布失败案例；签名与恢复演练完成后再称正式版。
3. **付费方向（后续）**：本地功能保持免费/开源；可选增值为“托管 AI 额度/团队版”，不要对本地核心能力收费。
4. **内容获客**：用“同一篇文章在 4 个平台的真实对照 + 质检问题单”做演示，比“支持多少平台”更有说服力。
