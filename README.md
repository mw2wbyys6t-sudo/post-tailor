OmniDraft 是一个本地优先的桌面应用（Electron）。它把"一篇文章复制到四个平台"这件事拆成三步：**先理解文章，再按平台重写，最后发布并看数据**。

它不承诺"必成爆款"。它做的是把爆款的前置条件变成可检查的项：钩子是否成立、结构是否符合平台、关键结论与数据有没有丢、有没有触碰平台禁忌。

## 为什么需要它

同一篇内容直接复制到四个平台，通常会在三处失效：

1. **结构不对**：CSDN 要结论先行 + 可复制的做法，小红书要短句清单，知乎要论证与边界，公众号要故事与金句。
2. **语气不对**：同一段专业表述，在公众号显得生硬，在小红书显得说教。
3. **效果看不见**：发完就结束，不知道哪个版本更好，下次仍然凭感觉。

OmniDraft 的答案是：**内容分析 → 平台规划 → 分平台成稿 → 本地质检 → 发布 → 回拉数据**。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 双模式编辑器 | 富文本（标题/加粗/颜色/列表/表格/图片/链接，实时目录）与 Markdown（编辑 / 双栏 / 预览）随时切换，保存统一落为 Markdown |
| AI 润色 | 已预置 DeepSeek（deepseek-chat）；一键润色当前文章，先看「润色前 / 润色后」对比与关键数字核对，再决定是否替换。每日本机账号限 20 次，失败或输出异常不扣次数 |
| 平台自适应改写 | 解析原文的章节、关键句、数字证据、代码与术语，判定内容类型（教程 / 经验 / 观点 / 测评 / 科普 / 案例），再按平台重排结构、语气与长度 |
| 双引擎 | 配置 AI（OpenAI 兼容）时走「计划 → 成稿 → 质检 → 按问题单修复」；未配置时用确定性本地引擎，只压缩原文事实，不编造 |
| 七维质检 | 信息保留、结构合规、长度、标题、原创度、可读性、平台合规；每项扣分都能定位到原因与修复建议 |
| 四平台发布 | CSDN（MetaWeblog）、微信公众号（官方 API，含封面图）、知乎（登录态接口）、小红书（浏览器自动填充，失败回退手动） |
| 批量发布 | 一次把已改写平台依次发出，逐平台显示结果，失败互不影响 |
| 数据回拉 | 单条 / 批量 / 定时回拉阅读、点赞、评论；不支持的平台明确显示「—」，不用 0 冒充 |
| 定时队列 | 入队后到点发布；应用关闭期间不执行，错过的任务会被标记 |
| 本地优先 | 文章、记录、改写稿、画像全部落在本机；凭据与 AI Key 进系统钥匙串加密 |
| 备份恢复 | 一键导出 / 导入全量 JSON（不含密钥），换机可迁移 |

## 平台支持矩阵

| 平台 | 登录方式 | 发布通道 | 自动发布 | 数据回拉 |
| --- | --- | --- | --- | --- |
| CSDN | 用户名 + 密码 | MetaWeblog 接口 | 支持 | 支持（解析文章页） |
| 微信公众号 | AppID + AppSecret | 官方素材 / 发布 API | 支持（含封面图） | 仅发布状态 |
| 知乎 | 扫码登录 | 登录态 + 网页接口 | 支持 | 支持 |
| 小红书 | 扫码登录 | 浏览器自动填写标题/正文 | 尽力而为，失败回退手动 | 暂不支持 |

> 微信阅读数据需要「图文分析」接口权限，普通账号无法获取；小红书没有第三方发布 API，采用浏览器操作官方发布页，页面改版时可能回退为手动确认。

## 快速开始

### 下载安装包

到 [Releases](https://github.com/mw2wbyys6t-sudo/post-tailor/releases) 下载：

- `OmniDraft-Win-x64-*.zip`：Windows 便携版（解压即用）
- `OmniDraft-Linux-x64-*.zip`：Linux 便携版

### 从源码运行

```bash
cd contentport
npm install
npm start        # 启动桌面应用
npm run dev      # 开发模式
npm run dist     # 打包当前平台
```

> 首次启动为**空白库**：没有预置文章、发布记录或统计数字。从「新建 / 导入文章」写下你的第一篇内容开始。

## 使用流程

### 1. 建立用户画像（可选）

回答问题说明你的创作领域、目标读者与风格，改写会据此调整措辞与深度。

### 2. 接入 AI（可选，已预置 DeepSeek）

设置中已默认填好 DeepSeek 的 Base URL 与 `deepseek-chat` 模型，填入 API Key 即可使用；Key 会存进系统钥匙串，明文不落盘。也可以在设置里点「使用 DeepSeek」恢复推荐配置。

接入后可用的能力：
- **AI 润色**：编辑器右上角，每天 20 次，先对比再替换；
- **AI 改写**：分发工作台的智能改写与单平台 AI 深度打磨。

不配置也能用：本地引擎会做结构重组、取舍、排版与长度控制，但不会生成新论据。

### 3. 绑定平台账号

在「账号中心」按平台登录。凭据加密保存，解绑时一并删除。

### 4. 导入文章并改写

1. 「文章库」→ 新建 / 导入：内置编辑器支持**富文本**与 **Markdown** 两种写法，Markdown 可切「编辑 / 双栏 / 预览」，左侧目录随标题自动生成
2. 「分发工作台」→ 选择目标平台 → 智能改写
3. 查看每个平台版本 + 质检分项 + 调整清单

### 5. 发布

- **发布到当前平台**：单平台立即或定时发布
- **批量发布已改写平台**：按顺序发完，逐条给结果
- 未登录账号时自动生成复制稿，正文不丢

### 6. 看数据与备份

「发布记录」可单条或批量回拉；开启自动回拉后按间隔更新，工作台会画累计阅读曲线。

「设置 → 数据备份」或「发布记录 → 导出备份」可导出全量 JSON；换机后导入恢复。

## 改写与质检怎么工作

```
文章(Markdown)
  ├─ 内容分析：章节 / 关键句 / 数字证据 / 代码 / 术语 / 内容类型
  ├─ 平台规划：钩子、结构模板、标题公式、字数预算、章节取舍
  ├─ 成稿：AI 三阶段（计划 → 成稿 → 修复）或本地确定性引擎
  └─ 质检：七维加权 + 硬门槛 + 可追溯问题单
```

**质检总分**

```
0.25×信息保留 + 0.20×结构 + 0.10×长度 + 0.10×标题
+ 0.15×原创度 + 0.10×可读性 + 0.10×合规
```

出现平台 P0 禁忌，或原文数字召回不足 80%，总分封顶 69 —— 宁可低分，也不给"看起来很好"的假高分。

**离线评测（10 篇文章 × 4 平台）**

| 平台 | 旧模板引擎 | 当前引擎 | 增益 |
| --- | --- | --- | --- |
| CSDN | 81.3 | 94.9 | +13.6 |
| 微信公众号 | 82.7 | 93.1 | +10.4 |
| 小红书 | 81.6 | 94.7 | +13.1 |
| 知乎 | 82.3 | 95.3 | +13.0 |

整体 94.5，P0 违规 0，长度合规 40/40。

> 这些数字说明"比模板拼装更能满足平台结构"，**不说明能获得多少阅读**。真实效果需要用各平台回拉数据校准。

## 数据与隐私

- **凭据**：平台账号与 AI Key 通过系统钥匙串（macOS Keychain / Windows DPAPI / Linux libsecret）加密，密文写入应用数据目录，权限 0600；系统不支持加密时直接报错，不静默降级。
- **内容**：文章、发布记录、改写稿、画像只存在本机，不上传。
- **网络**：仅在调用 AI、平台发布接口、数据回拉时出网。
- **备份**：导出的 JSON 不含任何密钥，恢复后需重新登录与填写 Key。
- **改名迁移**：应用品牌已从 ContentPort 更名为 OmniDraft，数据目录沿用原路径，已有数据不会丢失。

## 已知边界

1. **不承诺爆款**。质检分是代理指标，真正的验证是平台回拉数据；样本不足 30 条时不做结论。
2. **小红书**：无第三方发布 API，浏览器自动填充在缺图片或页面改版时回退手动确认；不支持数据回拉。
3. **微信公众号**：仅能回拉发布 / 审核状态，拿不到阅读数据。
4. **定时发布**依赖应用运行中；关闭应用期间不会后台执行。
5. **平台接口会变**：页面改版或接口调整可能导致通道失效，需要更新版本。
6. **AI 可选**：不配置 AI 时不会产生原文没有的论据，深度有上限。
7. **本地图片**：上传的图片会压缩后以 base64 内嵌在文章里（便于离线预览与复制），因此会占用本地存储；发布到需要图片外链的平台（如公众号素材库）时，可能需要改用图片链接。

## 目录结构

```
contentport/
├── electron/
│   ├── main.js              # 主进程：IPC、凭据保险库、扫码登录、小红书发布
│   ├── preload.js           # contextBridge 安全接口
│   └── platform/            # csdn / wechat / zhihu / xhs 四个发布通道
├── js/
│   ├── engine/              # 改写算法：analysis / strategies / planner / writer / quality / pipeline
│   ├── pages/               # 工作台 / 画像 / 文章库 / 画像基线 / 分发 / 账号 / 记录
│   ├── mock.js              # 平台画像与问卷配置（不含用户数据）
│   ├── state.js             # 状态、持久化、备份恢复
│   ├── api.js               # 改写、发布、回拉、凭据保险库
│   └── rewrite.js           # 旧规则引擎（仅作评测基线）
├── eval/                    # 零依赖评测集与 CLI
├── docs/demo/               # 使用说明 GIF
└── index.html / styles.css
```

## 开发与评测

```bash
cd contentport
npm test                # 冒烟测试：改写流水线 / Markdown 转义 / 演示数据清理
npm run eval            # 新旧引擎对比 + 阈值检查（不达标退出码 1）
npm run eval:ai         # 真实模型评测（需 AI_API_KEY / DEEPSEEK_API_KEY / AI_BASE_URL / AI_MODEL）
node eval/run.js --ai --cases=case-rag,case-short --platforms=csdn   # 小样本真实模型冒烟
npm run eval:baseline   # 刷新本地基线
npm run eval:calibrate -- --file=./history.json   # 用真实回拉数据做相关性校准
```

真实模型评测（`--ai`）看绝对分与 AI 成功率，不再用「相对旧引擎增益」作为门槛；回退本地引擎超过一半才会判失败。
